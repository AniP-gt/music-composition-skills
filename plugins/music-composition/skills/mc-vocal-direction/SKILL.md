# 歌唱ディレクションとハーモニー設計（Vocal Direction）

**このスキルでは、歌う音に加えて、ボーカルがどう歌うかを指定する。**

このライブラリでは、次の理由から特に重要になる。

> **AIボーカルの最もよくある弱点は「完璧さ」**。音程はすべて合い、強弱は平坦で、サビは毎回まったく同じように歌う。
> 人間の歌手にはできないし、そうしようとも思わない。

そこで、このスキルの半分は、**「完璧にしないでほしい」とどう指示するか**、そして**その指示をバックエンドが解釈できる言葉にする方法**を扱う。

## 作業に応じて参照する節

| 症状／作業 | 参照先 |
|---|---|
| ボーカルが平坦で表情に乏しい | §2 歌唱ディレクションの語彙 |
| ボーカルにもっとインパクトを出したい | §2.3 子音 |
| ボーカルの音程が「正確すぎる」ため機械的に聞こえる | §4 音程の考え方 |
| ボーカルが前に出ず、伴奏に埋もれる | §4.1（多くは音量以外に原因がある） |
| ハーモニーを足したいが、どのタイプか決められない | §5 4つのタイプ |
| ハーモニーがリードボーカルを覆う／出すぎる | §5 該当タイプのdelivery＋EQの考え方 |
| ダブルにするかどうか | §6 |
| Suno/YuE2用のボーカルプロンプトを書く | §7 |
| ARR-SPECのvocalブロックを埋める | §8 ＋ §9 |

## このスキルの適用範囲

| 対象外の作業 | 担当 |
|---|---|
| 歌詞の書き方、韻、語の声調と旋律の逆転（倒字）／音のなじませ方（协音） | **作詞**の工程。同じ曲の歌詞は `meta.upstream.lyrics` から読む |
| メロディの音高の動き、音域の設計 | `mc-melody`（L1） |
| 言葉を音に割り当てる（符割り/字余り） | **作詞**の工程。このスキルでは歌詞の行と切れ目に従って `breath_points` と `phrasing` を書く（1行を1フレーズとし、切れ目で息継ぎする）。歌詞がまだない場合はメロディのフレーズに従い、歌詞が届いたら改めて照合する |
| ボーカルEQの具体的な周波数、コンプレッサーのパラメーター | `mc-mix-intent`（意図）。実際の調整はミックスの工程 |
| ボーカルと帯域が重なる楽器の特定 | `mc-texture-layering` |
| 歌声合成音源（Vocaloid、Synthesizer Vのエンジンパラメーター） | 対象外。このライブラリでは歌唱意図を記述し（各バックエンドへの対応は§7）、エンジンパラメーターは扱わない |

## 1. 書き始める前に必ず埋める項目

| 必須項目 | 記述する内容 |
|---|---|
| **① 誰が歌っているか** | 声の人物像。性別、音域、質感、時代感。**「女性ボーカル」より具体的に書く** |
| **② 各セクションのdelivery** | 少なくともverse／サビ／ブリッジに分ける。「感情を込めて」のような曖昧な指示を避け、§2の語彙を使う |
| **③ 強弱の起伏** | セクション間の相対的な強弱。**lint #15が確認する。全曲が同じ強さなら不合格** |
| **④ サビごとの違い** | 2回目、3回目でそれぞれ何を変えるか（lint #16） |
| **⑤ ハーモニーの設計** | どのタイプ（§5）をどのセクションで使うか、主旋律の上か下か |

## 2. 歌唱ディレクションの語彙

### 2.1 音楽上の判断基準は2つだけ

> 1. **この曲に合っているか**
> 2. **この歌手に合っているか（似合っているか）**

基準はこの2つ。**技術の巧拙は基準から外す**。技術はそのための手段。
このライブラリでは、第2の基準を「**この声の人物像に合っているか**」とする。

### 2.2 ★ 「もっと大きな声で」と言わない

この節で最も実践的な指示。

> 壮大な編曲に対してボーカルがこもって聞こえるときは、**「もっと大きな声で歌って」と言わない**。音量はフェーダーで調整できる。
> 欲しいのはたいてい「**もっと明るい声**」なので、「**もう少し明るく歌ってください**」のほうが伝わる。

**情景や動作を思い浮かべられる指示**も効果がある。
- 「笑顔で歌って」
- 「口角を上げて」
- 「ずっと遠くに向けて歌って」

こうした言葉は、**テキストを受け取るバックエンドでも解釈しやすい**。
`sing brighter` / `smiling delivery` / `sung toward a far distance` は有効なプロンプト。
生成モデルでは `louder` で音量を制御できないため、ほとんど効果がない。

### 2.3 ★ 子音と母音を分けて考える

歌唱ディレクションと録音後の編集に共通する基礎。

- 1音節 = **子音＋母音**（「か」= K + A。ローマ字で書くと明確）
- **インパクトが欲しいときは、「大きな声で」より「子音を強く」が効く**
- 編集時は、**子音のタイミングの問題**か、**母音の長さの問題**かを見極める
- ミックスでは**子音のレベルを調整するだけ**でもボーカルの表情が変わる

### 2.4 魔法の子音「S」

> **S ≈ 口で作るホワイトノイズ。つまり本質的にはノイズである。**

この性質を編集に使える。
- **Sの途中でつないでも継ぎ目が聞こえない**
- **長さを自由に伸ばしたり縮めたりしても違和感が出にくい**
- 別のtakeからSを移植しても、ほぼ継ぎ目が分からない

> **★ 拍に合うのは母音。子音はその前に出る。**
> 「さ」(= S + A) を第2拍で歌うと、実際にはSが第1拍の末尾に来る。
> **拍にそろうのは母音Aである。**

**この考え方は2つの場面で使える**。
1. AI生成のボーカルを編集するとき、**「ここにSがある」=「ここでつなぎやすい」**
2. ボーカルの「前ノリ／後ノリ」を判断するときは、**音節の始まりより母音の位置を見る**。
   音節の始まりで判断すると、S、SH、TSから始まる音をすべて前ノリと誤判定してしまう

## 3. 映画と音楽の制作工程

映画制作の工程をポップス制作に当てはめると、次のようになる。

| 映画 | 音楽 |
|---|---|
| 脚本 | 作詞・作曲 |
| セットと衣装 | **編曲** |
| 俳優 | **歌手** |
| ヘアメイク | **現場での歌唱ディレクション** |
| 撮影 | 録音 |
| 編集 | treatment（ボーカルの調整） |
| MA | ミックス |

「現場でのディレクション＋録音＋treatment」の3つを合わせたものが**広義のvocal direction**。

生成モデルでは「録音」の工程がなくなり、
**「ヘアメイク」（ディレクション）と「編集」（調整）は残り、重要性が増す**。
モデルを制御できるのはディレクションだけで、出力を補えるのは調整だけだからだ。

## 4. ★ 音程の考え方

### 4.1 実測で得られた2つの知見

> - **低め（flat）に歌ったボーカルは、フェーダーをどれだけ上げても「前に出ない」**
> - **少し高め（sharp）のボーカルは「抜け」（伴奏を突き抜ける力）がよい**。うまい歌手は無意識に少し高めに歌う

1つ目から、よくある判断ミスを避けられる。**ボーカルが伴奏に埋もれたら、先に音程を確認し、その後で音量を見る**。

### 4.2 すべてを補正しない

> 「音程が合っているから歌がうまい」だけでは説明しきれない。逆に、**うまく歌う人はおおむね音程が合っている**。

そのため、次のように補正する。
- 伴奏が疎なところでは、高めや低めにずれた瞬間**そのものが味になる**
- 強調したいところでは**高めでもよい**。後から音程を上げる指示ではなく、歌手が「感情に任せて思わず高く歌った」箇所を**意識して残す**
- > **一部の音を意図的にそのまま残すと、自然なピッチ補正になる。**

**これは、このライブラリでAIっぽさを抑えるための中心的なボーカルのルール**。
生成モデルのボーカルはもともと音程がすべて合っているため、**どこで音程のずれを許すか**を指定する。

**記述方法**。ARR-SPECの `vocal.pitch_policy` には「音程を合わせる」という一律の指示を避け、「どこにずれを残すか」を書く。

**適用外となる場合**。編曲が極めて密でハーモニーを厚く重ねたセクションでは、音程のずれが濁りにつながるため補正する。**判断基準にはセクション名より伴奏の密度を使う。**

### 4.3 treatmentの3工程

1. **複数のtakeの継ぎ目を整える**
2. **リズムをそろえる**
3. **音程を補正する**

> **この順番にする理由**。先にリズムを調整してタイミングをずらしてからつなぐと、継ぎ目をもう一度直すことになる。

## 5. ハーモニーの4タイプ

**各タイプは、目的／delivery／リードボーカルを覆わない方法の3点で定義する。**
deliveryはこのスキル、EQは `mc-mix-intent` の担当。ここではEQの考え方までを扱う。

### タイプ1：歌い上げ上ハモ（しっかり声を張る上ハモ、通常は3度）

- **目的**。主旋律を保ち、全体を**より明るく華やかにする**
- **両立すべき点**。リードボーカルより音が高いため自然に目立つが、主旋律を覆わないようにする
- **★ 解決法**。「弱めに歌う」と華やかさが失われる。
  **しっかり声を張ったままEQで調整する**（リードボーカルの帯域からハーモニーを「逃がす」。低域を大きく削り、中域の「芯」を削る。必要に応じて高域を強調する）

### タイプ2：リードボーカルに寄り添う上ハモ

- **目的**。華やかさを抑え、**空気感を作ってコード感を出す**
- **★ 歌い方を変える**。声を張らず、**軽く、息を混ぜてクリーンに歌う**
- **注意**。音量は下がるが、マイクに近づくと近接効果で低域が上がるため、ゲインで補う

### タイプ3：控えめな平行下ハモ

- **イメージ**。**「リードボーカルが落とす影」**。原著の挿絵には、歌手とその影が描かれている。歌い方や発音はできるだけリードボーカルに寄せ、影に独立した表情は付けない (p0186)
- **存在感を抑える**。低域を削る。原著の参考EQ（6バンド）では、約110 Hzでローカットし、さらに123 Hzを−10 dB、247 Hzを−4.9 dB、621 Hzを−4.2 dB削る。単一点のノッチを作る方法ではなく、低域から中低域まで広く削る (p0186)

### タイプ4：合いの手（フレーズ間に入る短い応答、2–3声のユニゾン）

- **位置づけ**。リードボーカルとは**「別の音の要素」**
- **やり方**。**まずEQを使って**質感を変える（ラジオ風の音色でもよい。低域を削るだけでも雰囲気が変わる）
- **複数の声の一体感を高める**。フェーダー＋コンプレッションでレベルをそろえる → **グループに同じ空間系エフェクトをかける** →
  さらにグループ全体でモジュレーション系エフェクトを共有してもよい（チェーンはEQ → コンプレッション → コーラス → ディレイ）

### リバーブもタイプを決める要素

- タイプ 1、タイプ 2 では、**高域成分が豊かなリバーブやディレイ**で華やかさや空気感を補える。「主旋律のボーカルと帯域をずらす」という発想を、EQから空間系エフェクトにも広げるやり方 (p0186)
- タイプ 3 では、**直接音を減らして残響成分を増やす**と存在感を抑えられる。ウェットの比率を上げるほど、「この人が実際にここで歌っている」という実在感が薄れる (p0186)
- タイプ 4 の空間処理は、全体のまとまりを出すのが目的。同じ空間系エフェクトをグループ全体にかけ、質感をそろえる。本節のタイプ 4 を参照。リバーブの定位と主旋律のボーカルの定位の組み合わせ方は §6.2 を参照

## 6. Double と定位

### 6.1 主旋律のボーカルを Double する際のトレードオフ

> - **発音が非常に明瞭なボーカルをダブルにすると、言葉の輪郭が薄れる**
> - ただし、ダブル特有の安定したステレオ感には、**機械的な複製では出せない温かさと厚み**がある

★ 「機械的な複製では出せない」という点に注目。これは、
**生成モデルが直接出力する「ダブルトラック」が作り物っぽく聞こえる**理由でもある。複製では、2回目の歌唱で生じる違いが得られない。
本物のダブルにするには、1トラックをコピーして微調整する方法を避け、バックエンドで**2回目の歌唱を生成**する。

**作業の要点**
- **主旋律のボーカルテイクを先に決める**。歌い手はそのテイクを聴き、ぴったり合わせてダブルを歌う
- テイク選びに時間をかけると歌い手を待たせる。**発音の仕方を覚えているうちにダブルを録るほうがよい**（時間と品質のトレードオフ）
- 発音が複雑な曲は、**数フレーズずつ区切って丁寧に録る**
- **確認方法**。2トラックを左右いっぱいに振るか、**主旋律のボーカルをミュート**して、ダブルがしっかり合っているか厳密に確認する
- **指導方針**。**主旋律の言葉の輪郭を消さない**よう、ダブルは**発音を強調する歌い方**で録ってもらうとちょうどよい

### 6.2 定位の決め方

| 形態 | やり方 |
|---|---|
| **Single** | 特に理由がなければ**中央**に置く。音量、リバーブ、ディレイで主旋律のボーカルとの距離と奥行きを作る。極端に高い、または低い音域のハモリでは、**主旋律とは別のマイクに替える**ことも検討する |
| **Double** | 左右に振れる。**端に振るほど目立ち、小音量でも強調される**ので、目立たせたいものを大きく振る。上ハモと下ハモを両方ダブルにしたら、**大きく振るのは片方のペアだけ**。両方を振ると要素が多すぎる。編曲の中でハモリだけが広いと違和感が出る（意図的に使うことはできる）。**リバーブの定位も一緒に考える** |
| **Triple** | 「**single + double**」と考える。singleで奥行き、doubleで幅を出す。**singleの音量を下げる**とすっきりする |

### 6.3 ハモリの録音指導

主旋律をうまく歌える人でも、ハモリは意外に難しい。**ハモリと主旋律が微妙に似ていて覚えにくいため**。

**ガイドトラック（ガイド）が最も一般的な対処法**
- 新規トラックを作り、**アタックの弱い柔らかな音色**でハモリのラインを弾く
- 聴き取りやすくするには、**あえて1オクターブ上で弾く**。1 小節のラインを **2 小節のループ**にする。**ヘッドホンの片側だけに振る**方法もある
- 歌い手が慣れたら**ガイドの音量を徐々に下げ**、本番を録る
- **実際に歌って聞かせるのが最も効果的**。楽器の音色と人の声はまるで違う。
  楽器を弾かない歌い手には「頭の中で楽器の音を人の声に置き換える」ことが非常に難しい。
  歌詞の音節の割り当てが複雑なときは、特に難しくなる

> **このリポジトリでの対応**。生成バックエンドを使う場合、「ガイドトラック」は**モデルに渡す参照メロディーや参照音源**にあたる。
> 同じ理由で、**楽器のMIDIを渡すより、人の歌声を聞かせるほうが効果的**。

## 7. 各バックエンドへの落とし込み

| バックエンド | 受け付ける情報 | 書き方 |
|---|---|---|
| **Suno / MiniMax** | 自然言語による delivery の記述 | §2.2 の語彙を使う。例は `brighter`、`breathy`、`harder consonants`、`smiling`。**`louder` は書かない** |
| **YuE2** | 同上。曲のセクションごとに変えられる | セクションごとに delivery を書く。§1 の必須項目②に対応する |
| **MIDI / DAW（人が歌って録音）** | §2–§6 のすべて | そのまま direction sheet として使う |

**全バックエンド共通の2項目**
1. **曲のセクションごとに強弱を変える**（lint #15）
2. **サビは繰り返すたびに変化をつける**（lint #16）。ハモリを足す、delivery を変える、ダブルを足す、のうち1つ以上を行う

**バックエンド間の機能差への対応**。バックエンドが delivery の記述を一切受け付けない場合（`honors: none`）、
該当項目を0点とせず、指示の反映率を算出する際に**除外する**。詳細は L4 の backend profile のルールを参照。

## 9. 記入後の必須チェック

- [ ] 歌い手の人物像は、「女性ボーカル」という分類より具体的で、**どんな人が歌うか想像できる**
- [ ] 各セクションに固有の **delivery** があり、「明るく／息を混ぜて／子音を強く」のように歌い方へ落とし込める言葉を使っている
- [ ] **「もっと大きな声で」と書いていない**
- [ ] **曲のセクションごとに強弱が異なる**（lint #15）
- [ ] **サビは毎回変化があり**、何を変えたか説明できる（lint #16）
- [ ] `pitch_policy` では「音程を正す」という指示に終始せず、**どこでずれを許すか**を書いている
- [ ] ハモリのタイプを選び、そのタイプの **delivery と「主旋律を邪魔しない方法」の両方を書いている**
- [ ] タイプ 1 のハモリで、**「弱く歌う」ことで主旋律との干渉を避けていない**
- [ ] ダブルを入れる場合は、トラックを複製せず**2回目の歌唱**を求めている
- [ ] 上ハモと下ハモを両方ダブルにした場合、**左右いっぱいに振るのは片方のペアだけ**
- [ ] ボーカルの前ノリ/後ノリは、**母音**の位置で判断している

## 1. セクションを表す用語の定義

DeSantis「Common Forms 1: Elements of Song Form」による。
**ARR-SPEC の `form[].name` には、独自の命名を避け、この定義に沿った用語を使う。**

### Verse（ヴァース / "A" セクション）

- 通常は**繰り返し登場する**セクション
- 長さは通常 **16 または 32 小節**
- 曲の**主体**をなす
- 歌詞がある場合は通常、**物語を語る**

> DeSantis が各セクションの特徴を一覧にした事例は、判断の目安になる。ヴァースではマイクに近づいて息の多い小声で歌い、
> コーラスでは声をしっかり出して歌う。リードシンセは 2 回目のコーラスまで入らない。
> 曲式は Verse 16、Verse 16、Chorus 16、Breakdown 32、Chorus 16、Chorus 16 小節（p0018）。
> 小節数は曲によって変わるが、ヴァースをコーラスより軽く聴かせるという方針は共通している。
> まずは歌い方や楽器が入るタイミングで差をつけられる。トラック数の増減だけに頼る必要はない。

### Chorus（コーラス / "B" セクション）

- 通常は繰り返し登場し、**長さはヴァースと同程度**
- ヴァースの素材と**対比**をつくる
- 通常は曲の**フック（hook）**を含む。フックは聴き手の耳に残るように作った旋律のアイデア
- 通常は、**ヴァースで生まれた音楽的な緊張を解決する**
- ★ **重要な違い**<br>
  **ヴァースは繰り返すたびに同じ音楽を使うが、歌詞は通常変わる。
  コーラスは繰り返しても、音楽と歌詞は通常同じ。**
- 歌詞がある場合、コーラスには通常**曲名が含まれる**
- 原則として**最初のコーラスはヴァースの後に来る**（コーラスで始まる曲もある）

### Bridge（ブリッジ / "C" セクション）

- ヴァースやコーラスと**対比**をつくる
- 通常、**曲中に一度だけ登場する**
- 音楽的には他のセクションと**大きく異なる**ことが多い。**別の調**に移る、**珍しいコード進行**を使う、
  **テクスチャの密度やエネルギーの水準**を大きく変える、といった例がある
- ジャンルによってはブリッジで**楽器のソロ**を聴かせる
- 通常、**ヴァースとコーラスが少なくとも一度ずつ登場した後**に置く

> ★ コーラスの「同じ歌詞を使う」という定義は、本ライブラリの lint #16「コーラスを繰り返すたびに変化をつける」と両立する。
> **歌詞は同じでよいが、編曲には変化をつける。** DeSantis の定義は曲と歌詞の同一性を指し、lint は編曲を対象とする。

## 2. 商業音楽でよく使われる曲式

> **ABABCB** = Verse–Chorus–Verse–Chorus–Bridge–Chorus

- この基本形の最後に**コーラスを 1 回以上追加する**曲もある
- **ラジオで耳にするような現代のポップスの大半では、この曲式がそのまま使われる**
- **基本形に忠実な例**：Lorde《Royals》

### 2.1 この用語が当てはまりにくい場合

> ヴァース、コーラス、ブリッジだけを組み合わせた曲式は、**アンダーグラウンド寄りの音楽や実験的な音楽ではあまり使われない**。
>
> **ボーカルを伴わない現代の電子音楽では、多くのジャンルで従来のヴァースやコーラスを避け、
> レイヤーの増減（addition and subtraction of layers）で曲の展開に対比をつける。**
> （DeSantis「Common Forms 2: Layering as Form」参照）

**本ライブラリでの扱い**：ARR-SPEC の `form[]` はどちらにも対応する。
歌詞のある曲ではセクション名を使い、電子音だけで構成する曲では**レイヤー数の変化**で展開を表す。
後者のエネルギー曲線は `roster[].entry/exit` の変化から自然に生まれるため、セクション名をつけなくてもよい。

> これは `SKILL.md` §5「楽器編成の変化で曲式をつくる」の出典でもある。

### 2.2 DeSantis が最後に勧めていること

> ポップスに近いジャンルなら、**この数種類のセクションだけでも多くの曲を作れる**。

**単調さを避けるためだけに、新しい種類のセクションを作る必要はない。** 単調に聴こえるのは、同じ名前を使うからではなく、同じ処理を繰り返すからだ。

## 3. 本ライブラリの実測データ全表

分析対象は **Cambridge-MT のマルチトラック音源 62 曲**（意図的な選別をせずに抽出）。曲ごとに ARR-SPEC を逆算して作成し、各ルールの判定基準を満たした曲を集計した。

| ルール | 該当数・割合 | 区分 | 補足 |
|---|---|---|---|
| エネルギー曲線には必ず下降を設ける | **62/62** | **強いルール** | 例外なし |
| 曲の途中から入る楽器が必要 | **59/59** | **強いルール** | |
| 少なくとも 1 つの楽器が曲の終わりより先に抜ける | **59/59** | **強いルール** | |
| 全パートを厳密にグリッドに合わせない | **62/62** | **強いルール** | 適用外の条件は `mc-rhythm-section` §2.0 |
| 冒頭から全楽器を一斉に鳴らさない | **54/59** | **強いルール** | 5 件の例外はいずれも特定のスタイルに属する |
| 曲中で少なくとも一度、はっきりと音を減らす | **36/62 = 70%** | **傾向** | |
| 最大のクライマックス前にエネルギーを落とす | 全曲 **22%** ／ 人手による正解データ **5/7** | **★ 結果が食い違うため、手法として扱う** | §3.1 参照 |
| 最大のクライマックスで編成の密度が最も高くなる | **25/59 = 42%** | **保留** | |

**このほかの検証**：テンポの較正（正解データ 56 曲）、セクションの較正（人手でラベルを付けた 7 曲、正解率 72%、**ずれの中央値 0.0 s**）。

### 3.1 ★ 結果が食い違った理由

「最大のクライマックス前にエネルギーを落とす」に該当したのは、全 62 曲では **22%**、
**人手でラベルを付けた**正解データ 7 曲では **5/7** だった。

**差が出た理由**：アルゴリズムはエネルギーが最大になる位置を「最大のクライマックス」と判定するが、
人が聴いて感じるクライマックスは、**必ずしもエネルギーが最大の位置とは限らない**。
22% が示しているのは、エネルギーのピーク前に落ち込みがあった曲の割合だ。このルールへの該当率とは測っているものが違う。

**結論**：このルールは**根拠のないルールとして退けず、強いルールにも引き上げない**。
**手法**として扱い、`SKILL.md` では「こうしてもよい」という書き方にする。

> ★ これは本ライブラリで採用している検証方法の一例。**指標の精度が足りないときは、その数値で教科書の記述を覆す前に、
> 指標が測りたいものを本当に測っているかを確かめる。**
> （別の例は `mc-case-studies` §5.2。「12 dB のダイナミックレンジ」を固定値にした際の誤判定から得た教訓。）

### 3.2 根拠の強さに応じた扱い

| 区分 | SKILL.md での扱い |
|---|---|
| **強いルール** | 「必須」とし、20 項目のセルフチェックに含める |
| **傾向** | 「通常はそうする」と書く。lint には含めず、完成後のチェックリストに含める |
| **手法** | 「こうしてもよい」とし、症状別の診断でのみ扱う |
| **保留** | **スキルの本文には入れず**、データが増えるまで上の実測表のみに掲載する |

## 4. Suno のデフォルト傾向 → ARR-SPEC の対策フィールド

全 14 項目は `mc-ai-tell-audit` §2 を参照。ここでは照合しやすいように、編曲に関係する行だけを掲載する。

**使い方**：指示がないと、生成バックエンドは左列のような出力をしやすい。右列の ARR-SPEC フィールドでその傾向を抑える。

| バックエンドのデフォルト傾向 | ARR-SPEC の対策フィールド |
|---|---|
| セクションが同じ長さで、どれも 8 または 16 の倍数 | `form[].bars` + lint #3（すべてを 4 の倍数にしない） |
| エネルギーが最後まで単調に上がる | `energy_curve[]` + lint #1（必ず下降を設ける） |
| 冒頭から全楽器が鳴る | `roster[].entry` + lint #5 |
| 全楽器が冒頭から最後まで鳴る | `roster[].exit` + lint #6（少なくとも 1 つは先に抜ける） |
| 4 小節ごとにフィルが入る | `groove.fill_policy.bars` + lint #10（4 小節間隔で並べない） |
| 全パートが厳密にグリッドに合っている | `groove.push_pull` + lint #11（ずらす量を明記する） |
| 2 回目のコーラスが 1 回目とまったく同じ | `section_variation[]` + lint #16 |
| ダイナミックレンジが圧縮されて平坦になる | `dynamics[]` + lint #12 |
| ステレオの広がりが曲を通して一定 | `mix_intent.sound_stage[]` + lint #13 |

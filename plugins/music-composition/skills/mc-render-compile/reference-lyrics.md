# mc-render-compile リファレンス。生成先へ渡す歌詞の書式

> [SKILL.md](SKILL.md) §5.3 では、歌詞の取得元とセクション ID に沿った分け方を説明する。ここでは**分けた歌詞を生成先へ渡すときの書式**を扱う。改行、ブレス、母音の引き伸ばし、句読点と括弧、注釈、インストゥルメンタルのセクション、および送信前の確認事項を示す。
> 歌詞の原文は `meta.upstream.lyrics.sections` にあり、このスキル集では読み取り専用とする。記号の追加や削除は生成先に渡す版だけに行い、`render.<backend>` に書き戻す。
>
> ⚠ 母音を伸ばす表記、句読点と括弧、空行と1回の改行については一般的な目安を示す。生成先ごとの実際の挙動は実測を優先する。

---

## 1. 改行はフレーズの境界

歌詞欄では、同じセクション内でも改行のたびに楽句が区切られる（SKILL §5.3）。

| 渡す歌詞の形 | 生成先での解釈 |
|---|---|
| 1文を2行に分ける | **二つの楽句**。間にブレスが入る |
| 2文を1行にまとめる | **一つの長い楽句**。途中にブレスは入らない |
| 空行を挟む | 長めの間が入る |

`meta.upstream.lyrics.sections[].lines` の各要素を1行として渡す。行の結合や分割は行わない。

## 2. ブレスの位置を改行に合わせる

`vocal.breath_points` には、何行目の何音節目の後でブレスを入れるかを記録する。歌詞テキストだけを受け取る生成先では、ブレスの位置を改行で指定する。両者が合わない場合は次のようになる。

- **行の途中にブレスを指定した場合**、その位置でブレスが入らず、行末まで一息で歌う。
- **改行箇所にブレスを指定していない場合**、続けて歌わせる予定の2行の間にも間が入る。

表現できない箇所は、生成先の制約として `checks.exemptions` に記す。改行の変更が必要なら、セクションと行を明記した `messages` を `lyrics` に送る。リードシートや記譜形式では行中にもブレス記号（breath-mark）を置ける（`mc-symbolic-score`）。

★ **確認方法**。送る歌詞を行ごとに読み、行末で息を吸う。無理なく読めない箇所は、改行とブレスの位置を照合する。

## 3. 母音を伸ばす

歌詞のどの音節を伸ばすかは、生成先に渡す版の歌詞で明示する。よくある書き方は母音の反復（`a-a-ah`）やハイフンの使用。生成先によって異なるので、実測結果に従う。楽譜を渡す経路では音価を譜面に書くため、付加記号は不要。

## 4. 句読点と括弧

| 要素 | 生成先での一般的な処理 | 変換時の扱い |
|---|---|---|
| **読点・句点** | 無視されることが多いが、短い間になる場合がある | 省けるものは省く。間は改行で表す方が確実 |
| **丸括弧 `()`** | ★ ハーモニーやバックボーカルとして扱われやすい | バックボーカルやハーモニーの応答にだけ使う。**注釈は入れない** |
| **角括弧 `[]`** | ★ セクションのラベルとして予約されている | 歌詞本文に入れない |
| **三点リーダー・ダッシュ** | 挙動が一定しない | 避ける |
| **大文字**（英語） | 強調に影響する場合がある | 通常の書き方に従う |
| **注釈・制作指示** | ★ 歌詞として歌われる | ★★ 歌詞欄への記入を避ける。§5 を参照 |

## 5. 注釈は歌詞欄の外へ

歌詞欄の文字はすべて歌う対象になる。「ここを3回繰り返す」と書くと、生成先は**その文を歌う**。よく起こる誤りなので注意する。

- 編曲や歌唱の指示は style_prompt、`vocal`、`form[].note` に書く。
- 受け取った歌詞に制作指示が混じっていたら、指示を歌詞欄から除き、`form[]` に沿って反映する。リピートするセクションは繰り返し分のブロックを展開する。あわせて `lyrics` 宛ての `messages` を1件残す。

## 6. インストゥルメンタルのセクション

`[Instrumental]` の下は空欄にする。生成先はラベルからセクションの位置を判断し、その下にテキストがあると歌うべき楽句として扱う。
★ **ラベルは残す**。この枠を省くと後続のセクションが前にずれ、次のラベルがその位置に入る。イントロ、間奏、アウトロは `form[]` に ID があり、歌詞には対応する行がない。変換時は `form[]` に沿ってラベルだけを置く。

## 7. 歌詞を受け取る生成先と、倒字確認が有効な条件

生成先が歌詞を受け取るかは `backends.yaml` の `accepts.lyrics` を確認する。`false` の生成先（Stable Audio）はボーカルなしなので、歌詞を渡さない。記譜形式の場合は歌詞を譜面とともに渡す。ABC は `w:` 行、MusicXML は音節ごとに記録する。MIDI ではテキストイベントとしてのみ保持できる（`mc-symbolic-score`）。

★ **中国語の歌詞で行った倒字の確認は、指定した旋律が実際に使われる場合に有効。** 倒字は仕様書の旋律をもとに確認する。歌詞と譜面の両方を受け取る生成先（ABC を入力する YuE2）では指定した旋律を歌うため、生成前に倒字を確認できる。旋律をプロンプトで示す生成先ではモデルが旋律を作るため、生成結果でも確認が必要になる。

## 8. 生成先に渡す前のチェック（SKILL §11 に続く）

- [ ] 生成先が**歌詞を受け取れる**（`accepts.lyrics` が `false` でない）
- [ ] `meta.upstream.lyrics.sections[].lines` と同じ分け方で行を並べた
- [ ] 行ごとに読み上げて、行末でブレスできた。行中のブレスは例外として記録するか、変更を依頼した
- [ ] `[Instrumental]` は**ラベルだけを置いた**
- [ ] ★★ 歌詞欄から**注釈と制作指示を外した**
- [ ] 丸括弧は**バックボーカル**に、角括弧は**セクションのラベル**にのみ使った
- [ ] 句読点を最小限にし、間は改行で表した
- [ ] 中国語。旋律をプロンプトで示すだけの生成先では、**仕様書での倒字確認が生成結果を保証しない**ことを確認した

## 1. 意図を書く理由：ミックス内のスペースをめぐる競合

> ミックスの中では、各楽器が**聞こえるためのスペースを取り合う**。たとえば、ギターとボーカルは互いにマスキングを起こす (p0089)。

マスキングの定義と仕組みは Howard & Angus p0238–0239 を参照。同書ではボーカルと伴奏を例に、伴奏の 1.5 kHz 付近を少し下げ、ボーカルの同じ帯域を少し上げると、歌声が伴奏の中から浮かび上がると説明している（p0342）。
これがミックス処理で帯域を譲る基本形で、逆に処理するとボーカルはさらに聞き取りにくくなる。

ミックスエンジニアは、何を優先するかを決める必要がある。**意図を書かなければ、優先順位はエンジニアが普段のやり方に沿って決める**ため、曲の要望とずれることがある。
**ARR-SPEC の `mix_intent` には、その曲で何を優先するかをあらかじめ書いておく。**

## 2. ★ 作業順序の落とし穴：どのセクションから始めるか

Izhaki は 2 つの進め方を挙げ、最初の方法の落とし穴を指摘している (p0065)。

| 進め方 | 注意点 |
|---|---|
| **曲順に進める**（最初のセクションから順に処理） | 理にかなって見えるが、**Aメロを作り込みすぎると、サビで新たに加わる楽器を聞かせる余地がほとんど残らない** |
| **重要度順に進める** | 最も重要なセクションから処理する。録音作品では通常 **サビ**、電子音楽では **クライマックス** が該当することがある |

> ★ `mc-texture-layering` §6 の最大密度法と**同じ考え方**。
> **最も音が密な箇所を先に作り、そこを基準にほかの箇所を仕上げる**。音が少ない箇所から始めると、気づかないうちに残りの楽器を入れる余地を使い切ってしまう。

`mix_intent` の `focus_by_section[]` では、**最も音が密なセクションを先に書き**、残りのセクションはそこを基準に定義する。

## 3. トラック単位で進める 4 つのミックス手順 (p0064)

引き継ぎシートでは、**希望する作業順序をエンジニアに伝えると、最終的なスペースの配分が変わる**。

| 手順 | 利点 | 欠点 |
|---|---|---|
| **少数のトラックから順次追加** | 個々の楽器の処理に集中できる | トラックを追加するにつれて**ミックスのスペースが埋まり**、残りのパートを入れる余裕がなくなる |
| **リズム → ハーモニー → メロディー** | パートごとに段階を分けて録音する制作順序に沿っている | — |
| **重要度順** | 重要なトラックを最初に処理するので、**十分な音量で聞かせるためのスペースを確保できる** | — |
| **全トラックを並行して処理** | 常にほかのトラックとの関係を聞きながら作業できる | **比較的シンプルな編成の曲に限られる** |

（リズムトラック = ドラム、パーカッション、ベース。ハーモニートラック = リズムギター、Pad、キーボード。メロディートラック = ボーカルとソロ）

**本スキルの既定の推奨は重要度順**。理由は §2 と同じ。

### 3.1 ドラムセット内のミックス順序 (p0064–0065)

| トラック | 説明 |
|---|---|
| **オーバーヘッド（Overheads）** | 一般にステレオペアのマイクで収音し、**ドラムセットのほかの楽器を処理する基準**になる。先に処理する利点が多い |
| **キック（Kick）** | 多くの曲で**最も支配的な**リズム要素。ほかのドラムより先にミックスに加えることが多く、**オーバーヘッドに先行することもある** |
| **スネア（Snare）** | **2 番目に重要な**リズム要素で、キックの直後に処理することが多い |
| **タム（Toms）** | **特定の箇所でだけ鳴る**ため、ドラムセット全体のサウンドに与える影響が**最も目立ちにくい** |
| **シンバル（Hi-hat / Ride / Crash）** | オーバーヘッドのトラックに**かなりのかぶりがある**。個別トラックは、ミックスで**オーバーヘッドの効果を補強する**ためによく使われる |

> オーバーヘッドにはすべてのシンバルが収録されており、個別のシンバルトラックはその音を**補強する**役割を持つ。ドラムセットを構成する楽器は、この関係を踏まえて扱う。
> サンプルライブラリや生成バックエンドを使う場合は、マイクへのかぶりがなく、**そのかぶりが生むドラムセットの一体感が得られない**。補う必要があることを `mix_intent` に明記する。

## 4. 標準的なオーディオ処理の順序 (p0066、図 4.4)

処理の順序はミックス工程で決まる。引き継ぎシートにエフェクトを書くときは、その順序に従うため、ここに参照用として載せる。

1. **パンニングを省いて**素材をモノラルにミックスすると、**音の広がりと奥行きが失われる**
2. **インサートで処理した音が原信号に取って代わる**ため、モジュレーション、ディレイ、リバーブなどの**センドエフェクトより先に**処理する
3. 同じ理由で、通常は**モジュレーションをかけてからディレイをかける**
4. **リバーブは自然な空間の響きを再現する**ため、通常は**リバーブの後段にエフェクトを置かない**
5. **オートメーションは通常、ミックスの最後に行う主要工程**

**ドライ／ウェットの処理** (p0066)。まずすべてのトラックを**ドライ側のツール**（フェーダー、パンポット、プロセッサー）でミックスし、その後で**ウェット側のツール**（モジュレーション、ディレイ、リバーブ）に送る。

**リリース前の最終工程**では、通常、**定位とレベルバランスをさらに詰める** (p0066)。

## 5. 調整を重ねる：大まかなミックスから細部へ (p0067–0068)

> **「最初は大まかに作り、最後に細部を詰める。音を完璧に仕上げるのは、本当に必要なとき、つまりミックス工程の最後でよい。」** (p0068)

ミックスでは、それぞれの処理が密接に関係している (p0067)。

> 新しい素材を加えると、**すでにミックスした部分にも調整や仕上げが必要になることが多い**。
> 音を一箇所調整すると、**ほかの箇所でも追加の調整が必要になることがある**。

調整が連鎖する例 (p0067)。

1. ボーカルの高域を上げて明るくする
2. → リバーブで高域の**残響が長くなりすぎることがある** → ダンピングを調整する
3. → EQ によって**ボーカルの音量が上がったように聞こえる**（エネルギーがより多くの臨界帯域に広がると、音の強さの総量が同じでもラウドネスが上がる。Howard & Angus p0096）→ フェーダーを調整する
4. → ボーカルに EQ をかけてからコンプレッサーに通している場合 → **コンプレッサーの設定も調整が必要になることがある**

> ★ `mix_intent` に書くのは意図までとする。パラメーターは互いに影響するため、エンジニアの処理チェーンがわからないまま仕様書で一つの数値を固定すると、後に続く 4 工程の調整の余地まで奪ってしまう。

## 6. よくある 2 つの行き詰まりと対処法 (p0068–0069)

### 6.1 聴いても問題の箇所を特定できない

**症状**としては、どこかに違和感があるのに、**何が問題かを特定できない**。

**対処法**は、**リファレンストラックを使うこと**。
作業中のミックスを気に入っている完成ミックスと聴き比べると、**問題の箇所か、少なくとも次に試すべき方向**が見えてくる。

（リファレンストラックの 6 つの使い方は `SKILL.md` §6 を参照）

### 6.2 同じ調整を繰り返す

**なぜ起きるか**というと、**直近の数回の操作しか覚えていない**からだ。
2 日前にコンプレッサーで何をしたかは思い出せなくても、30 分前の EQ 調整はよく覚えている。その結果、直近の数件の判断の間を行き来する。

**対処法**

1. **短い休憩を取る**
2. **ミックス全体を聴き直し**、本当に必要な作業を見極めてから次の手を決める
3. > 「**直近のミックス処理を改めて評価する**ことを忘れないでほしい。」

Howard & Angus は同じ現象を「心理的な聴覚疲労」と呼ぶ。聴覚が音色の変化に順応すると、しばらくしてブーストの効果が弱く聞こえ、すでに順応した帯域をさらにブーストしてしまう。唯一の対処法は、いったん作業を中断して聴き直すこと（p0342）。
過大な音量による一時的な聴覚閾値の変化とは別の現象で、通常の音量でも起きる。

> ★ 同じことは agent にも当てはまり、影響はさらに大きい。
> agent が直近の記憶として使えるのは、コンテキストウィンドウ内の情報だからだ。
> **判断は ARR-SPEC に書き残し**、会話の中だけに置かない。
> 仕様書を読み直すことで、ミックス全体を聴き直すのと同じように、それまでの判断を見渡せる。
